# 08 — Outdoor terrain investigation

**Recommendation for review.** Start with a small, separate outdoor test area made from a few Blender-authored or Godot-native mesh tiles, with deliberately authored Godot collision. Keep the current playground as the flat comparison. Trial Terrain3D only if brush editing, foliage density or larger view distances become actual bottlenecks.

## Options

| Approach | Authoring and collision | Surfaces, vegetation and performance | Compatibility, automation and portability |

| Godot-native meshes or simple heightmaps | Edit small meshes or generate a grid from a height image. Use box/convex proxies, static concave mesh for shaped ground, or `HeightMapShape3D` for a matching height grid. Match grid origin and sample spacing across rendering and collision. Heightfields cannot represent overhangs. | Use materials or an authored blend shader. Place trees as separate scenes and consider spatially grouped MultiMeshes for dense grass. Existing MCP scene, resource and validation tools can wire and check the result. A small deterministic GDScript importer can be added if heightmaps become useful. ## Water and workflow

Keep water a separate Godot scene and material. Place a shallow stream surface against an authored bank or heightfield. Verify shore joins, depth appearance, shadows and collision for walkable ground. Terrain materials and foliage tools do not establish a water rendering or movement policy. A heightfield can define the riverbed, while separate meshes handle undercuts and banks with overhangs.

For the next review, use one small wooded slope, a path and a stream crossing. Preserve source geometry or height data, meter scale and tile origins. Test capsule grounding, uphill/downhill movement, seams, both camera modes, and daytime/nighttime readability. Track editing and reimport time alongside draw calls and frame time. Compare a plugin only after approval, in a disposable project on the exact engine and renderer. Require a successful clean checkout, export, collision check and recovery path for terrain data before adopting it.

The current performance baseline is in the [camera experiment notes](../prototypes/08-third-person-camera.md). Neither terrain plugin was installed or exercised. This recommendation leaves future terrain architecture open.
